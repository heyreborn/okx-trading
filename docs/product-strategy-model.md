# 产品与策略身份及绑定

状态：设计草案。本文定义多产品、多策略实例的稳定身份、关系和变更边界；具体 TOML 字段与数据库 schema 在类型化实现时冻结。OKX 产品字段和可交易范围以 [官方 API 索引](okx-api-reference.md#产品目录与行情)中的 `GET /api/v5/public/instruments`、`GET /api/v5/account/instruments` 及产品状态频道为依据，实现前逐项复核。策略类型和绑定关系是本系统内部设计，没有对应的 OKX 策略 API。

## 身份层级

| 对象 | 稳定标识与必要字段 | 所有者与约束 |
| --- | --- | --- |
| 交易环境 | `venue = OKX`、`environment = demo` | 环境进入所有外部身份的命名空间；首版不接受实盘。 |
| 产品 | 内部 `product_id`；不可变映射到 `(venue, environment, inst_type, inst_id)` | `instrument` 维护。`product_id` 是内部消息、账本和策略绑定的外键；OKX `instId` 只作为交易所标识。映射创建后不得原地改指另一产品。 |
| 产品类型 | 严格枚举 `Spot` 或 `LinearUsdtSwap`；同时保留 OKX `instType` 原值 | 产品类型随产品身份不可变；未知类型和非范围内合约拒绝。SPOT 基础币数量与 SWAP 张数保持不同单位。 |
| 产品规格 | `instrument_version`、来源与读取时间、状态、价格/数量步长、合约面值及币种等 | 来自 OKX 的可变事实，不嵌入 `product_id`；过期、变更或不适用时旧规划失效。 |
| 策略类型 | `strategy_type_id`、代码版本、参数 schema 版本、支持的产品类型/输入/输出能力 | `strategy` 的静态注册表拥有实现；同一类型可实例化多次。代码版本和类型 ID 分离，不用运行时任意动态库加载交易策略。 |
| 策略实例 | 全局唯一且不复用的 `strategy_instance_id`、`strategy_type_id`、`account_id`、参数/预算/状态及其配置版本 | 一个实例归属于一个账户，拥有独立状态、预热、预算和库存归属；多个实例可以使用同一策略类型。旧文档中的泛称 `strategy_id` 统一解释为实例 ID，协议新字段只用明确的 `strategy_instance_id`。 |
| 产品绑定 | 稳定 `binding_id`、`strategy_instance_id`、`product_id`、`role`；输入绑定另带频道/周期等 feed 规格 | `config` 校验关系，`observe_usecases` 按版本装载。一个产品可绑定多个策略实例；一个实例可读取多个产品并对声明的目标产品输出。同产品不同频道是不同输入绑定。 |
| 账户产品许可 | `(account_id, product_id)` 与本地准入状态、OKX 账户可交易事实 | 账户权限、持仓模式、杠杆/保证金条件与产品定义分开；公共产品存在不代表该账户可交易。 |

`product_id`、`strategy_type_id`、`strategy_instance_id` 和 `binding_id` 是不同类型，不能作为普通字符串互换。数据库分别为产品映射、实例 ID 和绑定 ID 设置唯一键与外键；输入绑定还按 `(实例, 产品, 频道/周期等 feed 规格)` 去重，目标绑定按 `(实例, 产品)` 去重。配置解析阶段检查悬空引用、重复绑定、冲突类型、跨环境引用及账户不匹配。展示名称、策略参数、产品状态、费率和规格可以变化，但不会改变这些稳定身份。

## 关系与执行边界

同一账户可以绑定多个 SPOT 和 USDT 本位线性 SWAP 产品；同一产品可以同时运行多个同类型或不同类型的策略实例。一个实例可使用多个输入产品，输出到一个或多个已声明目标产品。首轮验证可只配置每实例一个目标产品，但类型和关系不能把一对一写死。策略类型声明自己支持的产品类别、所需 feed、输出目标类型和持仓模式；配置绑定必须满足该声明。多个实例共享一个公共 feed，但各自维护状态和检查点。

下表只说明关系，不是可运行配置或 OKX 当前产品目录的声明；所有实例均属于同一示例账户。

| 内部产品与类型 | 策略实例（类型） | 绑定角色 |
| --- | --- | --- |
| `spot-a` / `Spot` | `trend-spot-a`（`trend`）、`mean-spot-a`（`mean_reversion`） | 两个实例都读取 `spot-a`，并分别向它输出目标。 |
| `swap-a` / `LinearUsdtSwap` | `trend-swap-a`（`trend`） | 实例读取 `swap-a`，并向它输出目标。 |
| `spot-a` / `Spot` | `trend-swap-a`（`trend`） | 仅作为跨产品输入；不因此获得 `spot-a` 的交易目标权限。 |

目标业务内容携带 `target_id`、`account_id`、`product_id`、`strategy_instance_id`、`strategy_type_id`、代码/参数/状态版本、绑定/配置版本、输入事件 ID 集和水位、有效期及目标单位；信封携带观察所有权代次。`portfolio` 按账户/产品合并目标，同时保留实例份额；`risk` 按账户、产品及实例预算计算准入与预留；`trader_usecases::approval` 在账户锁内核对最新事实并提交或拒绝本地批准；`accounting` 按实例和产品计算成交、费用与库存归属。一个实例输出多个产品时，每个目标独立可识别；OKX 不提供跨产品订单原子性，不把多目标输出解释成保证同时成交。绝对目标、`NoSignal`、冲突政策及接管见 [策略目标与实例执行协议](strategy-target-and-execution.md)。

行情事件携带内部 `product_id` 与原始 OKX `instId`，归档保留两者及映射版本；未知或冲突映射不能进入可信行情。Kafka 分区键使用稳定内部产品 ID；同一产品的多策略实例不导致重复采集。账户私有订单和成交还需携带 `account_id`，以免不同账户的同一产品发生归属混淆。

## 生命周期与变更

产品下架、禁用或账户失去交易资格只停止新的策略目标与开仓；已有持仓、订单、成交和审计继续引用原 `product_id`。产品类型或 OKX 标识改变须创建新产品映射，不复用旧 ID。规格变动增加版本并使引用旧规格的候选失效。

停用策略实例停止产生新目标，但不能删除其库存归属、未结订单、预留或历史决策。修改参数、预算、绑定或代码时发布新配置/策略版本，在检查点边界迁移状态；不兼容状态需新实例 ID 和经审计的归属迁移，不能静默清空或把旧实例库存改记给新实例。移除目标产品绑定前先核对该实例在该产品的持仓归属、未结订单和预留；无法结清时保持历史绑定只读。所有变更记录操作者、旧新版本、生效检查点和回滚依据。

## 实施前验证

- OKX 产品目录和账户目录能否按计划唯一映射到内部 `product_id`；未知 `instType`、同名不同类型、环境混用和规格变更要拒绝或显式迁移。
- 两个策略实例绑定同一产品、同类型多实例、一个实例跨产品输入/多目标输出、同一产品跨账户使用时，状态、预算、目标和成交归属不混淆。
- 禁用/删除/重绑实例时，未结订单、预留和库存仍可追溯；回放引用原产品、类型、实例和绑定版本。
- 产品规格或账户许可失效时，只暂停受影响的目标与订单；共享账户风险仍计入现有持仓与未结订单。

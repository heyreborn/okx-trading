# 模块文档规范

状态：实现前约定。适用于 `crates/`、`apps/` 和 `integration-tests/` 中的每个 Cargo package 及其中实际实现的 Rust module。文档与代码在同一次变更中提交；规划中尚未创建的模块不生成空白占位文档。

## 文档位置

- 每个 Cargo package 在自己的根目录维护 `README.md`。库 crate、`usecases` 库、`runner` 及单 package 应用均适用。它是该 package 的职责和实现说明入口。
- 每个 Rust module 在定义处使用 `//!` 说明功能、输入输出和关键约束。`lib.rs` 或 `main.rs` 的模块文档链接到同 package 的 `README.md`；重要的公开类型、trait 和函数使用 rustdoc 解释语义与不变量。
- 涉及多个 package 的消息契约、事务协议、故障恢复或技术选择继续放在 `docs/` 的专题文档中；package 文档链接到它们，不复制多份可能失效的规则。

## Package README 内容

每个 package 的 `README.md` 至少写清：

1. 功能和唯一责任：解决什么问题、不负责什么；所属进程或调用者，以及依赖方向。
2. 模块清单：每个实际存在的 module 的功能、主要输入输出和重要类型；新增、拆分或删除 module 时同步更新。
3. 实现流程：关键数据流、状态转换、异步任务所有权、并发控制、事务/消息确认点和外部依赖；纯计算模块只写适用的部分。
4. 约束与边界：身份与精度、时效、幂等、错误分类、重试/取消、暂停和恢复条件；明确哪些事实由本 package 拥有。
5. 依据与验证：对应的 `DEV-xxx` 任务、相关架构/协议文档、适用的 OKX 官方 API 链接、Python 已实现功能的行为证据、对应 Rust 测试与尚未验证的情形。Python 仅作功能参考，代码全部以 Rust 重写。
6. 重要取舍：影响正确性、性能或运维的实现决策、理由和已知限制。数值阈值注明配置来源、版本或待冻结状态，不把示例值写成固定规则。

不适用的项目用一句话说明即可。描述已经实现的行为时给出对应代码或测试位置；未来设计和已完成能力分开标记，不能用文档替代测试或模拟盘验收。

## Module rustdoc 内容

每个 module 的 `//!` 至少说明它拥有的行为、输入输出、依赖或调用边界，以及最关键的不变量。状态机、订单发送、对账、归属和异步任务等模块还需指出重复输入、超时、取消、乱序和恢复如何处理，并链接到 package README 的详细章节。公开 API 的文档写清单位、错误、可能的副作用和调用前提；示例只展示经过验证的用法。

## 同步检查

新增或修改 module 时，在同一变更中核对 package README 的模块清单与实现细节、module rustdoc、跨 package 专题文档和测试。代码评审检查文档与实际行为一致；CI 运行 `cargo doc --workspace --no-deps` 和 `cargo test --workspace --doc`。文档构建成功只证明链接和示例的部分问题，职责、故障语义和官方 API 来源仍需人工核查。

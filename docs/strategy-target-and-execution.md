# 策略目标、组合与实例执行协议

状态：设计草案。本文把 [产品与策略身份及绑定](product-strategy-model.md)延伸为可检查的运行契约。目标合并、策略状态与多机执行属于本系统内部规则，没有对应的 OKX 策略 API；订单和账户条件仍须逐项核对 [OKX 官方 API 依据](okx-api-reference.md)。具体字段名、超时与容量上限在类型化实现和真实基础设施测试时冻结。

## 目标的含义

策略实例对每个已绑定目标产品输出**该实例希望持有的绝对库存**，不是增减订单，也不是账户总仓位。SPOT 目标为非负基础币数量；SWAP 在净目标政策下为带方向的合约张数，在独立双侧政策下为各侧非负张数。目标类型、单位、产品、账户与持仓模式必须一致；账户当前持仓和在途订单仍由账本/远端事实提供，策略不得自行推断订单差额。一个实例有多个目标产品时，按产品分别标识和批准；策略的一次输出不能保证多产品订单原子成交。

每个目标至少携带 `target_id`、`account_id`、`strategy_instance_id`、`product_id`、`binding_id`、策略代码/参数/状态 schema 版本、配置/政策版本、输入事件 ID 与水位、来源时间、有效期、目标值与单位。信封另外携带观察执行代次、生成时间和发布尝试信息。`target_id` 由规范化业务输入及版本确定，不包含会在接管后变化的执行代次或生成时间；同一输入重放得到同一 ID 和业务值，同 ID 异业务值隔离。输入不齐、过期或 feed 不可信时不得生成新的可执行目标。

| 输出状态 | 含义 | 执行结果 |
| --- | --- | --- |
| `Target(value)` | 明确的新绝对目标；`value = 0` 是明确归零意图 | 进入组合与风险门禁；归零仍须可信仓位、订单及交易规则。 |
| `NoSignal` | 本轮不改变策略意图，也不延长上一目标有效期 | 不能触发新的订单；若已有目标到期，按过期规则处理。 |
| `Unavailable(reason)` | 输入或实例状态不可信 | 暂停该实例受影响目标的新执行并告警；不自动归零。 |

目标超过有效期、被新版本取代或所引用的绑定/账户产品条件失效时，禁止由它产生**新的批准或未发送订单提交**；未提交的意图及预留经状态核验后撤销/释放，已经提交远端的订单按订单恢复协议继续核对，不凭目标失效假定其撤销。目标过期不自动卖出或平仓。替换目标前核对旧目标关联的未结订单、预留与成交，避免两个版本同时按完整额度执行。有效期与输入窗口由策略类型声明上限，配置只能在上限内收紧。

## 同产品组合与归属

`portfolio` 以 `(account_id, product_id, 持仓侧别)` 为合并边界，使用各实例最新且有效的目标、实际实例归属、外部未归属仓位、未结订单和预留。每个实例目标仅对其**自身归属库存**产生所需调整。外部未归属仓位保留原归属并计入账户风险，不被策略目标吸收；本地归属与 OKX 账户总量不守恒时暂停该账户的新开仓并先对账。

初版组合政策为 `RejectConflicts`：同一账户/产品/侧别若有实例需要增加而另一实例需要减少，或净仓模式出现无法由实际归属支持的相反方向目标，不做隐式内部转移、虚拟对冲或任意优先级选择。记录冲突实例和差额，停止该批次的新开仓；已有风险降低动作按独立政策与可信事实处理。没有冲突时，同方向调整可以形成共享订单，但每个订单在批准事务中冻结实例份额、预算及余数分配顺序。成交和费用按冻结份额及实际成交增量入账，不能事后按最新目标重算。共享订单的部分成交、撤单及剩余预留必须逐实例守恒。

`portfolio` 只处理目标冲突、合并和实例份额，不判定账户/产品或实例额度是否充足。`risk` 基于锁内重新读取的账户事实、在途预留和候选判定预算；不足时初版拒绝该批次新增批准并记录具体限额，不静默削减所有目标，也不按实例 ID 排序抢额度。以后若引入比例分配、优先级、内部归属转移或跨产品组合约束，必须成为独立版本化组合政策，定义舍入余数、费用、策略权益、恢复和回放测试。候选冲突与预算拒绝不改变既有目标或已有持仓。

## 观察实例单活与检查点

Kafka 分区分配不能单独证明跨产品策略实例只有一个执行者。`observe_usecases` 为每个 `strategy_instance_id` 维护持久的所有权代次、状态检查点和目标发布进度；只有当前代次可提交新状态或目标。输入汇合按策略声明的时间窗口与确定性排序执行，不能依赖不同分区的到达顺序。观察者重平衡或失联时，接管者先读取已提交检查点及目标记录，再从可验证输入水位重放。

同一次实例推进将状态检查点、已处理输入身份、目标记录和目标 outbox 在 PostgreSQL 中原子提交，然后才确认 Kafka 消费进度。`observe_usecases` 负责目标 outbox 的可重投递交付；`trader_usecases::approval` 用 `target_id` 去重，并在组合前核对实例代次、绑定版本、目标有效期和同 ID 业务载荷。接管后相同业务目标可以保留原 ID 并带新代次；代次属于信封，不改变业务 ID。旧观察者即使仍在运行，也不能提交旧代次的 PG 事务；已在途的旧代次消息由下游隔离，不参与组合。接管期间该实例停止新目标，直到输入、状态 schema、版本与水位核对完成。目标交付传输方式、检查点格式、保留窗口和跨分区水位编码在实现前冻结；不得把 PG 事务提交与跨进程交付视为一个原子操作。

策略状态包含 `state_schema_version`、策略代码/参数/绑定版本、实例 ID、输入水位与有效性标记。代码或参数变化只有在对应状态迁移函数及回放测试通过后才复用检查点；不兼容时停用旧实例、保留其库存与历史，创建新实例并显式迁移归属或重新预热。重新预热不等于清空现有持仓；在未完成归属处理前，新实例不能接管旧实例的目标权限。单个实例的计算时间、状态大小和队列积压有上限，超限只暂停该实例及依赖它的目标，并向账户风险暴露其现有归属。

## 账户产品门禁

产品目录身份、策略绑定、账户产品许可是三个独立条件。`trader_usecases::approval` 对每次批准按 `(account_id, product_id)` 核对本地交易准入、OKX 实际可交易目录、产品规格与状态、账户持仓模式、适用保证金/杠杆事实、私有流及账户快照新鲜度，并让 `risk` 判定账户/产品/实例预算。`tdMode`、侧别和数量单位在规划时由已核验事实决定；配置不能声明一个不存在的交易所权限，也不自动修改账户模式或杠杆。相关 OKX 来源见 [账户及交易条件](okx-api-reference.md#账户费用与交易条件)和 [下单接口](okx-api-reference.md#订单回报与恢复)。

某账户失去产品许可时只暂停该账户/产品的新开仓；其他账户使用同一产品的关系保持独立。产品公共规格变动影响所有引用该版本的候选；账户模式或保证金事实变化影响对应账户及产品。已有持仓、未结订单和预留仍计入风险，风险降低动作按可信远端事实单独判断。配置发布、远端事实刷新和所有权接管均需重新执行门禁，不使用旧批准替代当前检查。

## 必须证明的行为

- `NoSignal` 不延长旧目标；`Target(0)` 不被当作缺失；输入失信和目标过期不会自动平仓或发出新订单。
- 同产品多实例反向调整、预算不足、净仓与双侧目标混用均明确拒绝；同向共享订单的部分成交、费用、撤单和余数分配逐实例守恒。
- 两个观察节点竞争同一实例、旧代次目标迟到、Kafka 重放及 PG 提交后发布失败时，只有一个有效目标版本进入组合。
- 策略代码/参数/绑定升级或回滚后，状态迁移、重新预热和旧实例归属保留可审计；不同版本的回放不覆盖原决策。
- 同一产品跨账户、账户许可变化、模式/杠杆事实变化及产品规格更新时，暂停范围和重新批准条件正确。

# 契约与不变量

状态：设计草案。本文定义 Rust 内部与持久化边界必须共同遵守的语义；字段名和 wire schema 在首个实现批次中冻结。交易所响应是外部输入，必须先解析和校验，再进入领域类型。模块归属见 [架构与功能归属](architecture.md)。

## 身份、版本与时间

| 对象 | 必备身份或版本 | 不变量 |
| --- | --- | --- |
| Account | `account_id`、实际账户/持仓模式、事实来源时间 | 本地 ID 不代替交易所账户事实；模式变化使旧规划失效。 |
| Product | 内部 `product_id`、OKX `inst_id`、`Spot`/`LinearUsdtSwap`、规格版本 | 内部 ID 不改指另一交易所产品；产品在白名单内且规格新鲜，合约面值与币种显式保存。 |
| Strategy type | `strategy_type_id`、代码版本、参数 schema 版本、支持的输入/输出类型 | 类型声明与实例身份分开；不兼容的产品类型或目标模式不得绑定。 |
| Strategy instance | 唯一 `strategy_instance_id`、类型 ID、账户 ID、参数/配置版本 | 同产品多个实例互不共享可变状态、预算或库存归属。 |
| Strategy-product binding | 绑定 ID、实例 ID、产品 ID、输入/目标角色、feed 规格及绑定版本 | 引用必须存在且类型/账户兼容；同产品不同输入频道不混淆，多对多关系不隐含跨产品订单原子性。 |
| Strategy target | 目标 ID、账户/实例/产品/绑定、版本、输入水位、有效期、绝对库存与单位 | 零目标、无信号和不可用不同；过期或旧代次目标不能产生新批准。 |
| Market event | schema/身份规则版本、稳定 `event_id`、来源命名空间、产品/频道、交易所时间、接收时间、来源会话、可选序列 | 同一采集记录重投递/回放保持同一 ID；跨连接同源识别须有稳定来源键；同版本同 ID 异业务载荷隔离报警。 |
| Decision | 稳定 `decision_id`、策略/配置/政策版本、输入事件 ID 集 | 相同版本与规范输入重放得到相同目标及拒绝原因；更改政策产生新决策身份。 |
| Order intent | 唯一内部意图 ID、稳定 `clOrdId`、账户/产品/模式/侧别、决策 ID | 同一已批准意图不能生成第二个可提交的交易所身份。 |
| Fill | 交易所成交身份、订单身份、数量、价格、费用及费用币种 | 重复回报只入账一次；成交可早于订单 WS 回报到达。 |

所有时间以 UTC Unix 毫秒存储；同时保留交易所来源时间与本机接收时间。判断新鲜度使用来源可信度和接收年龄，不以本机时间替代交易所时间。跨产品或频道没有天然全局顺序；同一输入集的规范排序键和迟到窗口在 `market` 固定。Kafka 位点表示消费位置，不等同于策略已经处理的事件。

产品、策略类型、实例、账户产品许可及绑定的完整关系见 [产品与策略身份及绑定](product-strategy-model.md)。配置/数据库/消息分别使用对应 ID 类型，禁止用 OKX `instId` 代替内部产品外键，或用策略类型 ID 代替实例归属。

### 行情事件身份

采集层给每条**规范化的业务事件**分配非空 `event_id`，发布到 Kafka、写入 Parquet、在线观察和历史回放都保留原值。ID 的命名空间至少区分交易所、环境、产品、频道、事件种类；每个频道的构造规则先以 [OKX 官方 API 依据](okx-api-reference.md#产品目录与行情)核对，再随消息 schema 版本冻结。若来源提供经验证稳定且唯一的交易/序列身份，可由来源身份确定性生成 ID，使断线重收、重复发布和归档重放仍得到相同 ID。不能仅凭价格、数量或时间戳推断两条推送相同；来源没有足够身份时生成采集 ID，并明确只保证该采集记录及其重投递稳定，不声称跨连接识别同一交易所事件。

`event_id` 是全链路去重、引用和审计键，不是全局顺序号，也不取代盘口 `seqId`/`prevSeqId` 连续性、Kafka topic/partition/offset 位置或消费者检查点。一个 WS 消息可能拆成多条业务事件；每条有自己的 `event_id`，原始消息另有来源会话和帧位置可追溯。去重检查比较同一 ID 下的规范业务载荷，接收时间、Kafka 位点和重试次数作为传输元数据单独保存；业务载荷冲突必须隔离告警。消费者以 `event_id` 做幂等处理，同时校验 schema、来源、产品/频道、序列与时效，不能只收一个 ID 就认为行情可信。

逐频道身份、采集所有权代次、schema 演进、去重窗口及 REST 补数规则由 [行情事件身份与采集接管](market-event-identity.md)定义。尤其未收盘 K 线的连续更新不能按周期键误删；无稳定来源键时多节点切换不能声称跨连接去重。

## 数值与单位

- 外部金额、价格、数量和比例从十进制字符串解析为 `BigDecimal`，禁止浮点路径、NaN 和无穷。每种领域类型携带币种或单位；SPOT 基础币数量与 SWAP 张数不能相加或隐式转换。
- OKX 产品规格决定价格 tick、数量 lot、合约面值和允许精度；规划器先计算，再按下单方向和交易所规则取整，最后重新验证名义金额、成本和风险。不得通过普通四舍五入制造超额预留。
- 中间计算使用显式精度上限、除法舍入模式与溢出错误；数据库列精度和领域上限在迁移前一同确定。值超出范围时拒绝计划，不截断或静默归零。
- `Money` 必须带币种。权益换算需要带来源时间的汇率/换算事实；不同币种费用分别入账，不能直接加到 USDT 盈亏中。
- 风险政策阈值与交易所事实分开：比例、预算和准入由版本化政策给出；余额、费率、杠杆、档位、规格和仓位由新鲜外部事实给出。

## 策略、组合与持仓

每个策略实例独立消费所绑定的 feed、预热并向已声明目标产品输出。一个产品可有多个策略实例，一个实例可读取或输出多个产品；目标为该实例自己的绝对库存，`portfolio` 先保留各实例贡献，再按账户/产品政策合并。净目标和独立多/空目标是不同类型，不允许静默转换。缺失、过期或不齐的跨产品输入不能生成新的开仓目标。初版反向调整或预算不足按明确原因拒绝新增批准，不暗中选择实例优先级。停用实例不删除其历史库存、在途订单或审计归属。完整状态及单活规则见 [策略目标与实例执行协议](strategy-target-and-execution.md)。

SPOT 现金模式目标为非负基础币数量。SWAP 数量为张数：`net_mode` 使用净仓政策；`long_short_mode` 可使用净政策或独立多/空政策。独立双侧政策在 `net_mode` 明确拒绝。双向账户同一合约的 `long` 与 `short` 是两条不同仓位，不得按净额消除毛敞口、实际保证金或策略归属。净仓越零先平旧方向，等远端成交和仓位核对后再计划反向开仓。

策略库存是本地归属记录，不是交易所子账户。共享订单的策略份额、逐笔成交数量和费用分配必须守恒；外部持仓保留“无策略归属”并计入账户风险。策略间现货库存转移必须原子记录，不能凭目标变化伪造交易所成交。资金费和实际手续费按交易所账单/成交核对，并保留产品、侧别与币种。

## 账户批准与订单状态

一个账户的所有产品共享权益、可用额、日损失、产品/账户净与毛敞口、策略预算和在途预留。批准事务锁定账户权威行，重新核验事实版本与所有权代次，原子写决策、订单意图、预留和 outbox。只有事务提交后才能调用 OKX。交易所多笔订单没有跨单原子性，单腿失败必须显式恢复。

订单状态至少区分 `reserved`、`submitting`、`unknown`、`live`、`partially_filled`、`filled`、`canceled`、`rejected`。累计成交数量只能增加，不能超过意图数量；终态不能被普通旧回报改写。`unknown` 表示提交结果或远端状态尚未核清，后续动作是按原 `clOrdId` 查询，而不是创建新身份重发。终态释放未使用预留后，账户快照必须重新核验。状态转换与逐笔成交入账分别去重，不能仅凭累计成交推导实际费用。

OKX 的 `clOrdId` 唯一性要求针对当前未完成订单及本次请求，不代表历史永久唯一；本系统长期不复用该 ID，并在首次获知后保存交易所 `ordId`。远端查询结果仍需与产品、账户、时间和已知订单事实交叉核对，不能只凭一个匹配的 `clOrdId` 解除未知状态。接口依据见 [OKX 官方 API 依据](okx-api-reference.md#订单回报与恢复)。

失去私有流、账户快照或产品行情可信度时，暂停相应新开仓。已有风险降低操作仍须基于可信仓位、订单和交易所规则独立判断，不能把“允许平仓”解释成绕过全部校验。冷静期、模式或杠杆等条件无法确认时不假定可交易。

## 协议与演进

消息 schema、行情身份规则、Parquet schema 和数据库 schema 分别版本化。网络消息拒绝未知必需字段、非法枚举与非法单位；增加字段时定义默认、迁移或显式拒绝规则。归档保留原始交易所载荷及规范事件；回放使用规范事件，并对同版本相同 `event_id` 的冲突业务载荷报错。跨 schema 版本比较按已验证的迁移规则进行；不能证明等价时隔离。任何改变决策排序、舍入、策略目标或订单身份的修改都必须增加版本并有回放/迁移测试。

待首批实现冻结的参数：每类金额和数量的领域精度上限、决策 ID 的规范编码与哈希算法、各频道的事件 ID 构成、排序延迟窗口、事实时效阈值和账户风险政策样例。冻结前先以 OKX 模拟盘只读响应、产品规格和极值测试验证；不得把这些值散落为代码常量。

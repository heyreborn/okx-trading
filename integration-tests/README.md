# integration-tests

Owns cross-package and isolated service acceptance tests. `src/lib.rs` documents the package boundary. `tests/connectivity.rs` invokes service clients inside an explicitly named Compose project to verify PostgreSQL, Kafka and signed S3 PUT/GET. `tests/stage1_catalog.rs` checks the model/config/instrument contract offline and contains an ignored, explicitly gated OKX demo Read-only directory check. `tests/stage1_numeric_pg.rs` is an ignored real PostgreSQL `NUMERIC(38,18)` round-trip and overflow test. `fixtures/connectivity-v1.txt` contains only a public marker; no account, market, or credential data is stored here.

The connectivity test requires `OKX_TEST_COMPOSE_PROJECT=okx-stage0-test-<suffix>` and refuses other project names. Start `deploy/compose/compose.yaml` under that project and run the `kafka-init` profile before `cargo test -p integration-tests --test connectivity`. The numeric test instead requires its own `okx-stage1-test-<suffix>` project with only healthy PostgreSQL and runs with `OKX_TEST_COMPOSE_PROJECT=... cargo test -p integration-tests --test stage1_numeric_pg -- --ignored`. It makes no persistent table. These tests use Docker CLI and container clients; Rust SQLx, rdkafka and object-store adapters do not exist yet. The connectivity test writes a repeatable object key and has no transaction or message offset ownership.

`cargo test -p integration-tests --test stage1_catalog` runs offline multi-product, multi-instance, both account-mode, wrong-unit, fee and freshness assertions. The real demo test is ignored by default. Local trader wiring lives in ignored, non-secret `.env.trader.local`: `OKX_TRADING_ENVIRONMENT=demo`, `OKX_TRADING_OKX_REGION=global` or `us`, `OKX_TRADING_CONFIG_PATH` pointing to a reviewed local TOML, and the three existing `OKX_TRADING_OKX_API_*_FILE` absolute secret paths. The secret files live in ignored `secrets/okx-demo/` with directory mode `700` and file mode `600`. For a one-time import from an existing private dotenv file, first create the parent with `install -d -m 700 secrets`, then run `cargo run -p integration-tests --example import_demo_credentials -- <source-env> secrets/okx-demo` and remove the source copy. The destination must not already exist. The importer selects only the three OKX credentials and never prints values. Runtime tests never read another project or the source dotenv file.

With an authorized demo account, run `OKX_STAGE1_DEMO_READ_ONLY=1 cargo test -p integration-tests --test stage1_catalog authorized_demo_catalog_acceptance -- --ignored --nocapture`. The test reads only this repository's local wiring, uses fixed demo endpoints and GET methods, and prints only account level, position mode, product/strategy counts and a config digest. A different account mode or unavailable product fails acceptance. The test owns no persistent state, retry or order submission; no application runner exists yet.

See [DEV-004, DEV-008 and DEV-013](../docs/development-roadmap.md), [stage-one acceptance report](../docs/stage1-acceptance.md), [testing strategy](../docs/testing-strategy.md), and [deployment](../docs/compose-deployment.md). Python's strict contract and catalog selection tests informed the offline boundaries, but all tests are Rust and assert this repository's own contract. One Global demo account passed the read-only check; a real net-mode account, application role wiring, SQLx and multi-node recovery remain unverified.

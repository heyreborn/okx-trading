# config

`deployment` parses process environment pairs into role-specific addresses and secret file references. PostgreSQL URLs require an explicit username but reject an inline password; the password comes from a secret file. It rejects unknown `OKX_TRADING_*` variables, non-demo environments, missing credentials, and credentials unrelated to the selected role. It performs no file or network I/O and cannot authorize trading. Runners will resolve and validate secret files later; this package never stores their contents.

`business` parses strict schema-one TOML into an immutable `BusinessConfig` with a canonical SHA-256 content digest. The product whitelist maps internal IDs to unique OKX IDs and SPOT/USDT-linear-SWAP kinds. Accounts list permitted modes and products; strategy instances have separate identity, budget, input-feed bindings and target-product bindings. A static capability list currently accepts `candle_momentum` with `candle1m` and `trade_flow` with `trades_all`; both can target compatible SPOT or SWAP products. This is a config declaration, not a running strategy implementation. Unknown fields, duplicate IDs, cross-product unit errors, unknown references, incompatible target modes, non-demo environments and `trading.enabled=true` fail. Callers may compare the digest to an expected publication digest. The parser does not read the file, check OKX account permissions or set a remote mode. Actual account eligibility must be checked again from fresh read-only facts.

Both parsers are synchronous and stateless. Errors identify categories or field names without values, and `SecretRef` redacts its debug representation. Node identity is bounded to 64 ASCII letters, digits, `-`, or `_`; secret paths must be absolute and cannot contain `..`. There is no retry, transaction, cancellation, or market fact here. Business policies are versioned local inputs; a digest mismatch prevents a node from accepting a different publication, but no multi-node publication protocol exists yet.

Basis: [DEV-005 and DEV-010](../../docs/development-roadmap.md), [configuration rules](../../docs/configuration-and-observability.md), and Python `app/settings.py`, `config/example.toml` and their tests. Python uses strict TOML and a disabled trading gate; Rust redefines the schema around distinct IDs and bindings. Unit tests cover role isolation, missing credentials, environment mixing, unknown overrides, redacted errors, valid multi-instance/cross-product config, duplicate or dangling bindings, incompatible modes, version digest and closed trading gate. Actual runner wiring, filesystem permissions, strategy implementation parity, remote account facts and distributed config publication are not yet verified. There is no OKX API call in this package.

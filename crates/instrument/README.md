# instrument

Owns pure read-only validation of the demo product directory. `src/lib.rs` defines immutable internal/OKX mappings, public instrument specifications, local account permits, actual account eligibility, fee facts and `Directory::assess`. It depends on `model` only; the future OKX adapter parses remote JSON, while a runner converts validated `config` entries into mappings and permits. No network call, file access, transaction, retry, cancellation or order submission exists here.

`Directory::new` rejects duplicate internal or exchange IDs, missing specs, mismatched product type/currencies and invalid tick/lot/minimum/contract values. SPOT sizes are base units; linear USDT SWAP sizes are contracts and require a positive contract value denominated in the base currency. `assess` checks the local product/account permission and observed remote account mode and eligibility, then requires `live` status, matching fee identity and fresh source plus receipt timestamps for specification, eligibility and fee. `post_only` is kept distinct and rejected by this initial gate. A successful assessment is only a read-only fact check, not approval to trade; planning must still validate current price bands, order type, leverage, balances and all risk conditions. Specs may change, so callers must carry versions and repeat checks before approval.

Basis: [DEV-011](../../docs/development-roadmap.md), [product identity rules](../../docs/product-strategy-model.md), [contract rules](../../docs/contracts-and-invariants.md), the OKX [public instruments](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-instruments), [account instruments](https://www.okx.com/docs-v5/en/#trading-account-rest-api-get-instruments), and [API change log](https://www.okx.com/docs-v5/log_en/), checked 2026-09-25. The public fields `instId`, `instType`, `ctType`, `ctVal`, `ctValCcy`, `tickSz`, `lotSz`, `minSz`, and `state` inform these types; account instruments require read permission and currently list 20 requests per 2 seconds by user and instrument type. The change log includes the `post_only` state and price-limit-band fields; the latter require separate planning checks. Python's `catalog/selection.py` is behavior evidence for whitelist plus account-mode/product-condition checks; Rust rules and tests are independently defined in `src/lib.rs`.

Unit tests cover mapping conflict, invalid spec, stale source facts, mismatched account mode and missing remote eligibility. Real OKX demo responses, fee-group selection, instrument version generation, and account-mode-specific remote availability remain unverified. The package does not claim a ready catalog service.

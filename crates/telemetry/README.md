# telemetry

Owns process diagnostics, not trading audit or recovery state. `log` installs a JSON stdout `tracing-subscriber` and emits fixed event/reason fields with bounded correlation IDs. `metrics` stores enum-keyed counters with a fixed label space. `health` tracks process liveness and explicit readiness transitions. Runners will initialize and export these facilities when they exist; no network endpoint or metrics exporter exists yet.

All modules are synchronous. Log writes are best-effort and are never an approval or transaction commit. Metric lock poisoning is recovered for diagnostics; counters saturate instead of wrapping. Health starts unready and cannot become live again after shutdown. The caller owns all underlying market/account fact checks, cancellation, retries, and recovery; `mark_ready` cannot lift a domain pause. Inputs are typed enums and bounded IDs, so no raw credential, request body, account response, or high-cardinality arbitrary label is accepted through these APIs. Other code must not bypass the allowlisted logger with raw sensitive `tracing` events.

Basis: [DEV-006](../../docs/development-roadmap.md), [configuration and observability](../../docs/configuration-and-observability.md), [failure recovery](../../docs/failure-and-recovery.md). There is no direct Python behavior to port for this foundation. Rust tests check JSON fields, rejected control characters, bounded labels, explicit health transitions, and that a failed log sink does not block caller state changes. Exporter integration, cross-node trace propagation, and actual ledger recovery will be exercised with later runners and persistence code; this package contains no OKX API use.

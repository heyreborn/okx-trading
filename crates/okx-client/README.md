# okx-client

Owns the initial read-only OKX demo REST adapter. `src/lib.rs` exposes fixed GET methods for system time, full or single allowlisted public SPOT/SWAP instruments, account configuration, account-visible instruments and fee groups. `ReadOnlyClient::new_demo` selects a known Global or US regional host; it disables redirects and ambient proxies, reuses a rustls HTTP client, requires `x-simulated-trading: 1`, and contains no POST or WebSocket method. A runner supplies demo Read credentials after resolving secret references. The client never stores ledger facts or approves an order.

The client synchronizes against `GET /api/v5/public/time`, rejects over-five-second clock skew, and uses its recent server-clock offset for ISO UTC millisecond signatures. Private GET signing covers timestamp + `GET` + path including the query string; the HMAC-SHA256 result is Base64. Calls are conservatively serialized at 500 ms intervals; time sync also has a five-second per-client interval. Requests time out after five seconds, are never retried automatically, and reject redirects, non-200 HTTP, nonzero business codes, bodies over 1 MiB, missing fields and unknown required enums. Errors contain only a bounded numeric business code, never response text or credentials. A server-clock-derived observation time and local receipt time accompany each response. Fee data update `ts` is preserved separately from read freshness.

Parsed decimals use the `model` exact domain. SPOT base/quote currencies come from `baseCcy`/`quoteCcy`; a SWAP must be linear, USDT-settled, with positive `ctVal` and `ctValCcy`. `to_instrument_specs`, `to_eligibility` and `to_fee_schedule` explicitly convert read-only responses into `instrument` facts. Their versions hash normalized specs or fee data; `instrument::Directory` still checks immutable local mappings, account permission, actual mode, fee group, state and freshness. Returning an account-visible ID does not imply a trading permission. Client construction per process must be controlled so rate limits are not bypassed with multiple instances; distributed rate coordination is not implemented.

Basis: [DEV-012](../../docs/development-roadmap.md), [OKX API reference](../../docs/okx-api-reference.md), [official API v5](https://www.okx.com/docs-v5/en/), and [change log](https://www.okx.com/docs-v5/log_en/), checked 2026-09-25 for demo headers, REST signature, time, public/account instruments, account configuration, fee groups, documented units, permission and rate limits. Python's `exchange/okx_transport.py`, `catalog/selection.py` and contract tests were behavior references; Rust signs, parses and validates independently. Mockito tests cover HMAC against an independent OpenSSL vector, demo/auth headers, code/status errors, malformed and oversized bodies, SPOT/SWAP units, fee groups and adapter-to-directory conversion. They use dummy credentials and a local fake server. Regional demo access, current account permissions, clock behavior over a real network, paging beyond the documented array response, remote error variants and simulated-account facts remain unverified; there are no real OKX calls in these tests.
